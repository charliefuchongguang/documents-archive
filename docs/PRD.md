> 项目名称：公路招标代理项目档案归档管理工具
> 版本：v1.0
> 状态：✅ 已确认

> **2026-10-30 变更：** 本文档中「项目」的旧定义（卡片列表、四个并列入口、合同—项目关联）已由《需求变更-2026-10-30-项目管理模块》v1.4 覆盖。系统主对象为「归档项目」；「工程项目」是业主的立项工程，仅用于分组；合同台账独立且仅管理员可见，不参与业务统计。

## 一、产品概述

本工具面向公路行业招标代理公司的从业人员，解决项目档案归档过程中手动填写管理表耗时耗力、容易出错的问题。用户将项目相关文档（已用 MinerU 预转为 Markdown）上传至企业微信自建应用，系统自动提取关键信息填入标准化的项目档案管理表（30个字段），经用户确认后同步至企业微信智能表格。

目标用户：招标代理公司的项目管理人员，非技术背景，习惯使用企业微信办公。

## 二、核心功能需求

### 功能1：项目创建与草稿管理
- **描述**：用户可以创建新的归档项目，系统为每个项目生成唯一ID。项目支持分批上传文件，未完成的项目以草稿形式保存在本地。
- **用户操作**：
  1. 点击「新建项目」按钮
  2. 输入项目名称（可选，默认为"未命名项目"+日期）
  3. 进入项目详情页
- **预期结果**：页面显示项目卡片，列出已上传的文件和提取状态（未上传/已上传待提取/提取完成）

### 功能2：文件分批上传（6类文档）
- **描述**：每个项目支持上传6类归档文件（输入格式统一为 `.md`）。用户可随时补传缺失的文件，已上传的文件可重新上传覆盖。
- **支持的文件类型**：
  | 文档类型 | 对应提取字段 | 是否必填 |
  |----------|-------------|---------|
  | 招标公告截图 | 公告时间、公告媒体 | 否 |
  | 招标文件 | 项目编号、项目类型、省份、行业、项目名称、招标类型、招标方式、建设类型、里程、道路等级、项目概况、总投资、招标人、联系人 | 是 |
  | 中标通知书 | 项目名称(校验)、中标单位、中标金额、中标通知书时间、盖章单位、招标人(校验) | 是 |
  | 中标公示 | 公示时间、中标单位(校验) | 否 |
  | 履约评价 | 评价书出具时间、负责人/参与人员(校验) | 否 |
  | 代理服务合同 | 合同名称、委托时间、项目负责人、技术负责人、其他参与人员、委托金额、联系人 | 是 |
- **用户操作**：在项目详情页点击对应文档类型的「上传文件」按钮，选择本地 `.md` 文件
- **预期结果**：文件上传成功，显示文件名，状态变为「已上传，点击提取」

### 功能3：AI 自动信息提取
- **描述**：用户点击「开始提取」后，系统调用 DeepSeek API，将 Markdown 文本内容发送给大模型，按预定义的字段模板提取结构化信息。每类文档独立提取，提取结果合并到项目总表中。
- **提取策略**：
  - 每类文档单独调用一次 API，减少单次请求长度
  - 使用结构化 Prompt，明确要求模型返回 JSON 格式
  - 对枚举值字段（如项目类型、招标方式、盖章单位），要求模型从给定选项中选择最匹配的
  - 对日期字段，要求统一返回 `YYYY-MM-DD` 格式
  - 对金额字段，要求统一返回数字（万元）
  - 如果某字段在文档中未找到，返回 `null` 或 `"未找到"`
- **用户操作**：点击「开始提取」按钮（可单文件提取，也可一键提取全部已上传文件）
- **预期结果**：显示提取进度，完成后展示提取结果预览

### 功能4：提取结果复核与编辑
- **描述**：将 AI 提取的30个字段以表单形式展示，用户可逐项核对、修改、补充。对于同一字段有多来源的（如项目名称来自招标文件和中标通知书），显示来源标记和冲突提示。
- **用户操作**：
  1. 在表单中直接修改任意字段的值
  2. 对冲突字段（不同来源值不一致），系统高亮显示，用户选择采用哪个来源的值或手动输入
  3. 点击「保存草稿」随时保存修改
- **预期结果**：所有字段确认无误后，「提交至智能表格」按钮变为可用状态

### 功能5：同步至企业微信智能表格
- **描述**：用户确认数据无误后，一键将项目数据写入企业微信智能表格。如企业微信 API 暂不可用，降级为导出 Excel 文件。
- **用户操作**：点击「提交至智能表格」按钮
- **预期结果**：
  - 成功：显示「同步成功」提示，智能表格中新增一行数据
  - 失败：显示错误原因，提供「导出 Excel 手动导入」降级方案

### 功能6：项目列表与状态管理
- **描述**：首页展示所有项目（进行中/已完成），支持搜索、筛选、删除。
- **用户操作**：
  1. 在首页查看所有项目卡片
  2. 点击项目卡片进入详情
  3. 删除已完成或废弃的项目
- **预期结果**：项目列表实时更新，草稿项目保留在本地存储中

## 三、交互流程

### 主流程：新建项目 → 上传文件 → 提取信息 → 复核 → 同步

```
用户打开企业微信 → 点击工作台「档案归档助手」
  → 进入项目列表首页
  → 点击「新建项目」
  → 输入项目名称 → 进入项目详情页
  → 上传招标文件（.md）→ 点击「提取」
  → AI 提取完成，显示结果预览
  → 上传中标通知书（.md）→ 点击「提取」
  → AI 提取完成，与招标文件结果合并
  → （按需继续上传其他文件并提取）
  → 点击「查看完整表单」进入复核页
  → 核对30个字段，修改错误项
  → 点击「提交至智能表格」
  → 同步成功，返回项目列表
```

### 异常流程：AI 提取失败

```
用户点击「提取」
  → DeepSeek API 调用失败（网络/Key 无效/服务异常）
  → 显示具体错误信息：「API 调用失败：[错误原因]」
  → 提供「重试」按钮
  → 如 Key 无效，提示用户去「设置」页面更新 API Key
```

### 异常流程：字段缺失

```
用户进入复核页
  → 某字段显示「未找到」（AI 未从文档中提取到）
  → 字段背景标黄提示
  → 用户手动输入或留空
  → 留空字段在提交时提示「以下字段为空，确认提交？」
```

## 四、数据与存储

- **存储方式**：纯前端 IndexedDB（通过 localForage 或 Dexie.js 封装）
- **数据内容**：
  - 项目基础信息（ID、名称、创建时间、状态）
  - 已上传文件的原始 Markdown 文本（用于重新提取）
  - 每类文档的提取结果（JSON）
  - 合并后的最终表单数据（30个字段）
  - DeepSeek API Key（加密存储或仅存于 localStorage）
- **数据格式**：
  ```json
  {
    "projectId": "proj_20250508_001",
    "projectName": "G8517高速可研招标",
    "status": "draft",
    "createdAt": "2025-05-08T09:00:00",
    "files": {
      "tender_doc": { "filename": "招标文件.md", "content": "...", "extracted": {...} },
      "bid_notice": { "filename": "中标通知书.md", "content": "...", "extracted": {...} }
    },
    "mergedData": {
      "projectNo": "ZEC-Z25F-011",
      "projectName": "...",
      "...": "..."
    }
  }
  ```

## 五、边界条件与限制

- 输入文件统一为 Markdown 格式（用户预先用 MinerU 将 PDF/图片等转换）
- 纯前端实现，无后端服务，数据仅保存在当前设备的浏览器中
- 企业微信智能表格同步依赖企业微信 API 权限，如未开通则降级为 Excel 导出
- 评标报告不参与信息提取（用户确认）
- 同一项目内的文件应属于同一招标项目，系统不做跨项目校验
- 单次上传文件大小限制为 10MB（Markdown 文本通常远小于此）

## 五-A、AI API 集成规范

> ⚠️ 本项目使用 DeepSeek API 进行文本信息提取

### API Key 管理（强制要求）

1. **严禁在代码中硬编码 API Key**
2. **必须提供「设置」入口**：在页面右上角放置设置按钮（齿轮图标 ⚙️）
3. **设置弹窗内容**：
   - DeepSeek API Key 输入框（密码模式，显示为 `••••••`）
   - API 基础地址输入框（默认 `https://api.deepseek.com`，支持自定义代理地址）
   - 「保存」按钮 → 将 Key 存入 `localStorage`
   - 「清除」按钮 → 从 `localStorage` 删除 Key
   - 「测试连接」按钮 → 调用一个简单的 API 请求验证 Key 是否有效
4. **首次使用提示**：如果检测到 `localStorage` 中没有 Key，显示友好提示：「请先在设置中配置 DeepSeek API Key」
5. **代码读取方式**：`const apiKey = localStorage.getItem('archive-helper-deepseek-key')`

### API 调用注意事项

- 使用 DeepSeek Chat API（`v1/chat/completions`），模型推荐 `deepseek-chat`
- 每次请求携带完整的字段提取 Prompt + Markdown 文本内容
- 要求模型返回严格的 JSON 格式，设置 `response_format: { type: "json_object" }`
- 错误处理：
  - API Key 无效：提示用户检查 Key
  - 网络超时：提供重试按钮
  - 模型返回非 JSON：尝试正则提取，失败则提示用户手动填写
- 费用预期：单次提取约消耗 2k-5k tokens，按 DeepSeek 定价约 0.001-0.003 元/次，单个项目完整提取（6份文件）约 0.01-0.02 元

## 六、不在本版本范围内

- 用户登录/权限管理（企业微信自建应用自带身份）
- 后端数据库存储与多设备同步
- 自动识别文件类型（用户需手动选择上传的文档类别）
- PDF/图片直接上传（统一由用户预先用 MinerU 转为 Markdown）
- 批量创建项目（后续可考虑模板导入）
- 数据统计与报表（如月度归档项目数统计）
- 智能表格的双向同步（仅支持从应用写入表格，不支持表格修改反向同步到应用）
